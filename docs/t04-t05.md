# T04 혼잡도 판정 기준 · T05 이용자 웹 (ADE-8 / ADE-9, 도형준)

## T04 — `backend/congestion.py`

- `judge(value, values) -> (score, level)`: 해당 시간대 과거 분포 안에서의 midrank 백분위 점수(0~100)와 단계.
- 경계값은 상수 `QUIET_MAX = 35`, `NORMAL_MAX = 70` (포함). 이름 quiet/normal/busy는 공통 규격 v1 고정, 숫자만 조정합니다.
- `backend/prediction.percentile`은 이제 `judge`에 위임합니다. 판정 로직은 이 파일 한 곳에만 있습니다.
- 빈 분포·None 값은 `(None, None)` → 웹에서 "판정 불가"로 표시. 전부 같은 값이면 50 → normal.
- 근거 자료: `python -m scripts.congestion_report [records.json] [--weeks N] [--json out.json]`
  → 시간대별 n / p35 / 중앙 / p70 / "여유≤ x명" / "혼잡> y명" / 단계 비율 표. 실제 records로 돌려 경계값 조정 근거로 첨부합니다.
- 테스트: `tests/test_congestion.py` (경계 포함 여부, None, 동일 분포, 위임, 요약).
- T01 P1(운영시간 08~20) 승인 시: 분포 계산 시간 범위만 좁히면 됩니다(`domain.HOURS`).

## T05 — `frontend/`

- `api.js`: `BASE_URL` 한 곳 + `api.meta / api.today(date) / api.stats(date)`. 오류는 `{code, message}` ApiError로 통일.
- `app.js`: 화면 로직. 데이터는 api.js를 통해서만 받습니다.
- 표시: 기준 날짜 / 지금 시간대 혼잡 단계(오늘일 때만 큰 글자, 다른 날짜는 안내 문장) / 추천 시간 / 시간대별 막대(탭하면 상세) / 평소 대비·근거·표본 수 / 실제 집계 / 갱신·기준 시각.
- 상태: 합성 샘플 배너(`is_sample`), 예측 자료 부족(`expected_visitors: null` → 회색 막대·"자료 부족"), 해당 날짜 집계 없음(`DATA_NOT_FOUND`), 서버 오류·네트워크 오류(`#error`).
- 문구: "예상 방문량 기준 · 현재 체류인원 아님"을 상단에 항상 표시. 실시간 체류인원 표현 없음.
- 모바일 390px 기준 설계, 600px 이상에서 표 기본 펼침. `scripts.e2e` 통과(16 막대·갱신 반영·390px 가로 스크롤 없음·오류 화면).
- T06 API로 교체 시: `BASE_URL`만 바꾸고, 응답 필드가 `docs/architecture.md`의 today/stats/meta와 다르면 `describe()`와 `load()`의 해당 줄만 수정.
